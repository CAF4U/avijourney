# CAF4U Aircraft Companion V0.3 Implementation Brief

## Objective

Rebuild the proven FlightScope V0.2.5 concept as a clean Flutter/Dart Android-first application named CAF4U Aircraft Companion.

The goal is not feature expansion. The goal is to establish a production-worthy mobile foundation while reproducing and improving the proven live-aircraft experience.

## Reference prototype

Repository: `Hugo-Doswald/flightscope-prototype`  
Reference milestone: V0.2.5 / commit `82729ea`

V0.2.5 proved installable Android delivery, live OpenSky data, HexDB enrichment, radar, cards, aircraft detail, filters and useful portrait/landscape interaction.

## Required screens

### Radar

- Circular ATC-inspired radar.
- Default range: 20 NM.
- Tap visible range badge for 20 / 80 / 140 / 200 NM quick choices.
- Range remains in settings too.
- Aircraft plotted geographically relative to radar centre.
- Heading-oriented markers.
- Trails use observed positions only.
- Label density adapts to range.
- Selected aircraft stays identifiable.

### Map

The V0.2.5 static map background is explicitly rejected.

V0.3 requires a real slippy map with correct latitude/longitude projection, pan, pinch zoom, selectable aircraft, persistent viewport state and replaceable tile/provider implementation.

### Cards

Each card should support primary identifier, callsign, operator, type, registration, origin/destination airport codes and smaller airport names, altitude, speed, heading, vertical-rate state and saved state. Cards must scroll naturally.

### Aircraft detail

Display primary identifier, callsign, operator, model/type, route with airport codes/names, registration, altitude, speed, heading, vertical rate, squawk, observed trail/history and useful provenance.

### Filters / Settings

Include radar range, refresh interval, altitude min/max, trails, labels, saved-only, provider/feed status and reset.

Suggested refresh choices: 30 s, 60 s, 2 min, 5 min. Explain that faster refresh consumes more free-provider quota.

### Saved

Persist saved aircraft locally across restart.

## Data requirements

### Position

OpenSky is the initial provider. Model ICAO24, callsign, latitude, longitude, altitude, speed, track, vertical rate, squawk, last-contact/age and on-ground when available.

### Enrichment

HexDB is the initial enrichment provider. Cache registration, type, model, operator, callsign route and airport metadata.

### Commercial flight number

Never infer from an alphanumeric ATC callsign. Create a future `FlightIdentityProvider` abstraction; V0.3 may use a no-op implementation.

Identifier priority:

1. verified commercial flight number;
2. callsign;
3. registration;
4. ICAO24.

## Free-first behaviour

- Cache live responses for short intervals.
- Cache aircraft identity by ICAO24.
- Cache route resolution.
- Cache airport metadata as near-static data.
- Stop or slow network work in background.
- Preserve last usable snapshot on rate-limit/provider failure and mark it stale.

## App lifecycle

Provider failures must not prevent the app shell rendering.

States: starting, connecting, live, cached/stale, offline, rate limited, provider error.

## Mobile requirements

Android first. Respect safe areas, portrait/landscape, touch, vertical scrolling and responsive relayout. No controls under system UI. Rotation must relayout rather than rotate a portrait-sized layout.

## Out of scope for V0.3

Fare shopping, ticket booking, guessed flight numbers, accounts/cloud sync, social features, paid API dependency and full trip planning.

## Deliverable

A tested Flutter Android app whose live-aircraft experience is clearly superior to V0.2.5 in map accuracy, maintainability, mobile behaviour and data architecture.
